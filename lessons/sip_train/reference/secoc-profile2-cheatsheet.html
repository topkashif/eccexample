Profile 2 at a glance

A compact reference for configuring one AUTOSAR SecOC Profile 2 secured PDU in Vector MICROSAR Classic.

Security boundary. Profile 2 authenticates data origin and integrity, but has no synchronized freshness value. Replaying a previously valid secured PDU is not prevented by SecOC Profile 2 alone.

Protocol target

ItemRequired value
MAC algorithmAES-128 CMAC, NIST SP 800-38B
Authenticator in secured PDU24 most-significant bits of the CMAC output
Freshness in secured PDUNone
Complete FV lengthSecOCFreshnessValueLength = 0 for the no-FV form
Truncated FV lengthSecOCFreshnessValueTruncLength = 0
Truncated authenticator lengthSecOCAuthInfoTruncLength = 24

AUTOSAR Protocol R24-11 section 5.3.3 lists the no-FV form as 0/0/24. The same section also shows a conflicting legacy table row (not specified/8/24); use the explicit no-FV row when the requirement says “no FV”.

Authenticated input

DataToAuthenticate = SecOCDataId (2 bytes, big-endian) || AuthenticPdu

For the normal full-PDU case, Vector's CSM43 authenticator inserts the configured 2-byte Data ID at the beginning of the authentication buffer and calls Csm_MacGenerate. With no FV, the complete FV contributes zero bytes.

Secured-PDU layout

Authentic PDU || Truncated Authenticator (3 bytes)

The authenticator is copied from the MAC cache using big-endian bit-copy logic. The exact offset depends on the generated PDU layout, but 24 bits normally occupy three complete octets at the end.

DaVinci configuration map

SecOC

Per TX/RX processing

  • Create matching SecOCTxPduProcessing and/or SecOCRxPduProcessing.
  • Set the same SecOCDataId at both ends.
  • Set SecOCAuthInfoTruncLength = 24.
  • Set SecOCFreshnessValueLength = 0 and SecOCFreshnessValueTruncLength = 0.
  • Use a normal non-split secured PDU for the first bring-up.
Csm

Crypto path

  • Create an AES CMAC CsmPrimitive.
  • Create a CsmJob for MAC generation and verification as required by the package.
  • Reference the AES-CMAC primitive and the key.
  • Confirm synchronous/asynchronous processing matches the driver and SecOC timing.
Integration

Runtime

  • Call SecOC_InitMemory if startup does not do it.
  • Call SecOC_Init.
  • Schedule generated SecOC_MainFunctionTx/Rx instances if deferred.
  • Connect Csm to the RH850/ICUSE crypto driver through the delivered Vector/Renesas integration.

Common traps

  1. Setting only the transmitted FV length to zero but leaving the complete FV length nonzero.
  2. Using 24 bytes instead of 24 bits.
  3. Using the least-significant CMAC bits instead of the most-significant 24 bits.
  4. Changing the Data ID or byte order between sender and receiver.
  5. Assuming a hardware ICUSE capability is automatically used: SecOC calls CSM; the CSM job/primitive/driver mapping determines the implementation.
  6. Enabling development mode, ignore-verification, or forced pass in a production security configuration.

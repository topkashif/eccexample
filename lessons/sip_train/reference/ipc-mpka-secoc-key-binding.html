Reference card · IPC security integration

Bind the MPKA key to SecOC—without confusing jobs, keys, or lengths

IPC uses MPKA key-negotiation group 2 with IPC local ID 3 and EVCU local ID 4. The final message-group key—not the exchange key—must protect SecOC.

Evidence boundary. The supplied vKeyM_MPKA source orchestrates ECDH and X9.63-SHA256 KDF, but the inspected CryptoWrapper key-exchange and KDF hardware hooks return E_NOT_OK. This card defines the correct binding; it does not claim MPKA is target-ready.

For two present members, vKeyM_MPKA selects ECDH. The local member is implicit; do not add IPC as a remote member. Keep the temporary key separate from the committed final key.

CSM binding

SecOC authentication-layer ID
  → CsmJob
  → CsmJobKeyRef = MAC_Final_2
  → AES-CMAC primitive
  → CryIf / crypto backend

The value passed as the first argument of Csm_MacVerify() is a job ID, not a key ID. Never hard-code BOOT_MAC_KEY in a generic wrapper.

Adapter lifecycle

Configure generated key/job handles
  → wait for vKeyM_MPKA_KeyNegotiationFinalized(2, SUCCESSFUL)
  → Csm_KeyElementGet(CddMsgGrpKey, CRYPTO_KE_MAC_KEY)
  → require exactly 16 bytes
  → SecLib_KeyRAMUpdate(key, 16)
  → activate adapter
  → route only registered SecOC job IDs

Loading into ICUS KEY_RAM copies key material through CPU memory. It requires readable final-key material and an ownership policy for the shared RAM slot. If the key is non-readable/hardware-bound, bind SecOC directly to the CSM/CryIf key instead.

Verification input

SecOCDataId       = project-configured two-byte value
Authentic PDU     = project-configured bytes
Csm input length   = Data ID + Authentic PDU (+ FV if configured)
Csm MAC length     = 24 bits

For the existing lesson's Profile 2 contract, the expected input is 02 02 || 5-byte Authentic PDU, length 7, with no freshness bytes. Reconfirm this for IPC before freezing the adapter constants.

Do not do this

  • Do not define a second global Csm_MacVerify(); it risks duplicate symbols/recursion and bypasses generated job dispatch.
  • Do not replace MPKA ECDH/KDF with SHE M1–M5 or SecLib_CalculateKdfSHE().
  • Do not assume a generated trigger response means the key is committed or usable.
  • Do not treat ICUS KEY_RAM loading as persistent protected-slot provisioning.
  • Do not treat CSM request E_OK as MAC verification success; inspect verifyPtr.

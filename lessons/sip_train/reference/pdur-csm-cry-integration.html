Reference card · integration

SecOC module interaction map

RX data path

CanIf → PduR → SecOC → Csm → Cry_30_Rh850Icus → ICUSE
                                     ↓
PduR ← verified Authentic PDU ← SecOC
ModuleResponsibility
Can / CanIfReceive the 8-byte CAN-HS frame and provide the PDU indication.
PduRRoute the secured PDU to SecOC and the verified Authentic PDU onward.
SecOCExtract the 5-byte Authentic PDU and 3-byte MAC, assemble `02 02 || AuthenticPdu`, request verification, and forward only after success.
CsmResolve the job ID, prepare the crypto job, and dispatch `Csm_MacVerify` to the referenced primitive.
Cry_30_Rh850IcusExecute AES-CMAC verification using the configured RH850 ICUSE service/workspace/key mapping.
ICUSEHardware security execution layer used by the RH850 Cry driver.

HV_BATT values

secured PDU = 8 bytes
Authentic PDU = bytes 0..4
padding bytes 3..4 = 00 00
MAC = bytes 5..7, 24 bits
CMAC input = DataId 02 02 || bytes 0..4

DaVinci tree

Can / CanIf
  └─ global HV_BATT PDU, length 8
PduR
  ├─ lower CanIf Rx → SecOC secured-layer Rx PDU
  └─ SecOC Authentic PDU → upper PDU / COM
SecOC
  └─ SecOCRxPduProcessing
      ├─ secured PDU reference
      ├─ Data ID bytes 02 02
      ├─ AuthInfoTruncLength 24 bits
      ├─ FV length 0
      ├─ FV trunc length 0
      ├─ secured-Rx verification TRUE
      └─ deferred processing initially
Csm
  └─ CsmJob
      ├─ CsmJobPrimitiveRef → AES-CMAC primitive
      ├─ CsmJobKeyRef → configured key
      └─ processing mode
Cry_30_Rh850Icus
  └─ CryCmacAes128VerConfig
      ├─ CryLengthInBytes consistent with MAC length convention
      ├─ CryKeyIdType
      └─ workspace

Integration checklist

  1. Configure and generate Can/CanIf global 8-byte PDU.
  2. Route CanIf Rx to SecOC through PduR.
  3. Configure SecOC RX Profile 2.
  4. Configure Csm primitive, key, and verify job.
  5. Configure Cry CMAC verification service and connect it through the delivered Cry/CryptoIf/CryIf path.
  6. Generate and inspect job IDs, PDU IDs, Data ID bytes, lengths, and references.
  7. Initialize Csm, Cry, and SecOC in the generated startup order.
  8. Schedule SecOC RX main; schedule Csm/Cry main functions for asynchronous processing.
  9. Verify valid, modified-payload, modified-padding, and modified-MAC frames.

The exact symbolic container names can vary by Vector package; use the delivered BSWMD and generated references as authority.

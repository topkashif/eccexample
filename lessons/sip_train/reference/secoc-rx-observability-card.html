Reference card · RX verification

Prove RX SecOC without an application ACK

Pipeline

CANoe 8-byte frame
 → PduR Path A
 → SecOC_RxIndication
 → SecOC_RxIf_RxIndication
 → SecOC_MainFunctionRx / SecOC_Verify_MAC
 → Csm_MacVerify
 → Cry callback
 → SecOC_RxCsmCallback, if async
 → PduR_SecOCRxIndication
 → COM/application, 5 bytes

Breakpoints

FunctionExpected evidence
SecOC_RxIndicationSduLength = 8; if uninit branch fires, prove init set TRUE and no later clear
SecOC_RxIf_RxIndicationnormal PDU copied; MAC cached
SecOC_MainFunctionRxInternaldeferred RX processing is scheduled
SecOC_Verify_MACverification state machine starts
SecOC_VerifyProcessing_MACUsingCSM43Data ID/authentic data/MAC/24-bit length sent to CSM
Csm_MacVerifygenerated authentication-layer job is requested
SecOC_RxCsmCallbackasync CSM result returns to SecOC
PduR_SecOCRxIndicationverified Authentic PDU forwarded, length 5

Expected input

Data ID       = 02 02
AuthenticPDU = CAN[0] CAN[1] CAN[2] 00 00
CMAC input    = 02 02 || AuthenticPDU
received MAC  = CAN[5] CAN[6] CAN[7]
MAC length    = 24 bits

Invalid-frame evidence

bad payload/padding/MAC
 → Csm_MacVerify
 → verification != OK
 → ProcessUnsuccessfulVerificationResult
 → no normal PduR_SecOCRxIndication to COM

Do not confuse

  • CAN controller ACK ≠ SecOC verification success.
  • Status propagation NONE ≠ verification disabled.
  • Five-byte Authentic PDU ≠ eight-byte secured CAN frame.
  • CSM request accepted (E_OK) ≠ MAC verification result is OK; inspect the result pointer/callback.
Check bypasses: development mode off, ignore-verification off, verification override cancelled.

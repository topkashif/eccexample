Each name above denotes a CsmKey:
CsmKeyRef → CryIfKey → CryIfKeyRef → driver CryptoKey

shared secret → KDF → temporary AES key
                           ↓ group confirmation
                      final AES key → SecOC CSM MAC job

The group key must support Vector's ECBD key workflow even if only two ECUs are currently present. The driver template named KeyExchange_NISTP224R1_BD is the technical reference's starting point for either supported curve; sizes must match the chosen curve. Read §5.4.

3 · Enter one group

  1. In the Basic Editor, open vKeyM_MPKA → Cdd. Set the OEM local ECU ID and curve in CddGeneral.
  2. Create remote-member entries and bind each to its own MPKA RX contribution.
  3. Create CddKeyNegotiationGroup: OEM group ID, SecOC negotiation type, required X or X-and-Y shared-value mode, local TX contribution, remote-member references, and KEX_Group.
  4. Create CddMessageGroup: OEM message-group ID and the three remaining CSM-key references shown above. Leave CddMsgGrpTmpKeyMacSec absent for this SecOC case.

Instance names here are teaching names, not existing project handles. Curve and shared-value mode must match the OEM requirement and all peers. Exact fields, defaults, and constraints.

4 · Check the units

For AES-128 CMAC, the final key is 16 bytes. The Profile 2 authenticator on CAN is 3 bytes. Do not make the MPKA key three bytes long. Read §5.7.1.

5 · Keep negotiation traffic separate

MPKA uses 64-byte messages for secp224r1 and 72-byte messages for secp256r1, including its own 8-byte header. Neither fits one Classical CAN frame. Do not route the earlier HV_BATT PDU into MPKA or switch a generic selector to TP without an implemented adapter. Read §5.10–5.11.

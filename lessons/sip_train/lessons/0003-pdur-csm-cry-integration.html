Lesson 03 · integration map

Trace one HV_BATT frame through PduR, SecOC, Csm, and ICUSE

This lesson gives you the integration order and the DaVinci configuration shape for your RX-only Profile 2 use case.

Mission link. The goal is not merely to make SecOC compile. It is to prove that the exact 8-byte CAN-HS frame reaches SecOC, that SecOC authenticates the correct 7-byte logical I-PDU input, and that the CSM job executes on the RH850 ICUSE driver.

Local evidence: SecOC requires PduR_SecOCRxIndication and Csm_MacVerify; SecOC_RxIndication receives the secured PDU; the RX implementation forwards the Authentic PDU to PduR after processing. The local CSM implementation stores the input and MAC pointers in a job object and calls Csm_ProcessJob.

2. What PduR does—and does not do

PduR only routes the PDU between the lower communication stack and SecOC, then routes the verified Authentic PDU onward. It does not calculate CMAC, interpret the SecOC Data ID, remove the MAC cryptographically, or decide whether verification passed.

3. DaVinci configuration shape

CAN / CanIf

  • Define the 8-byte CAN-HS `HV_BATT` message and its CAN ID.
  • Map the received CAN L-PDU through CanIf to a global secured PDU.
  • Ensure the PDU length is 8 bytes.

PduR

  • Source: lower IF PDU from CanIf.
  • Destination: SecOC secured-layer RX PDU.
  • Route the verified Authentic PDU from SecOC to the upper destination PDU, normally toward COM.
  • Use direct IF routing initially; avoid queues until the basic path works.

SecOC

  • Create `SecOCRxPduProcessing` only.
  • Reference the 8-byte secured PDU.
  • Set `SecOCAuthInfoTruncLength = 24` bits.
  • Set complete and truncated FV lengths to zero.
  • Configure Data ID bytes `02 02` according to the generated first/second-byte fields.
  • Use the complete 5-byte Authentic PDU so padding bytes 3–4 are included in CMAC.
  • Enable `SecOCSecuredRxPduVerification`.
  • Use `DEFERRED` processing initially.

Csm

  • Create/select an AES-128 CMAC CsmPrimitive.
  • Create one CsmJob for MAC verification.
  • Reference the CMAC primitive and the key.
  • Set the job processing mode to match the CRY driver integration.
  • Reference the CsmJob from SecOC's authentication layer/job reference.

CRY / RH850 ICUSE

  • Enable the `CryCmacAes128Ver` service and its generated configuration.
  • Configure MAC length interpretation consistently: the local BSWMD has `CryLengthInBytes`, default true; reconcile this with SecOC passing 24 bits and the driver configuration.
  • Configure key-ID interpretation and workspace.
  • Initialize the CRY driver during startup.
  • Schedule its main function if the chosen service is asynchronous.

5. Integration order

  1. Import the compatible BSWMDs and verify AUTOSAR release compatibility.
  2. Configure Can, CanIf, and the 8-byte global HV_BATT PDU.
  3. Configure PduR routing into SecOC and from SecOC to the upper layer.
  4. Configure SecOC RX processing and Profile 2 parameters.
  5. Configure Csm key, AES-CMAC primitive, and verification job.
  6. Configure Cry_30_Rh850Icus `CryCmacAes128Ver` and connect the Csm primitive to it through the delivered Cry/CryptoIf/CryIf integration.
  7. Generate and inspect references: secured PDU, Authentic PDU, authentication job ID, Data ID bytes, authenticator length, and PDU lengths.
  8. Integrate initialization: startup memory initialization, Can/CanIf/PduR/Csm/Cry/SecOC initialization in the project’s generated order.
  9. Schedule `SecOC_MainFunctionRx`; schedule `Csm_MainFunction` and CRY main function if asynchronous.
  10. Test with a known-good frame, then mutate authentic data, padding, and MAC separately.

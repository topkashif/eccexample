4 · The two cryptographic formulas

Seal / verify (every day use)

CMAC = AES-128-CMAC( DATASTORE_KEY, payload[0..47] )   → stored in block[0..15]

Registration transport (once, at provisioning)

K1 = KDF(KEY_AuthID, KEY_UPDATE_ENC_C)      K2 = KDF(KEY_AuthID, KEY_UPDATE_MAC_C)
M2 = ENC_CBC,K1,IV=0 ( Counter(28) | KEY_FLAG(6) | "0…"94 | KEY(128) )
M3 = CMAC_K2 ( M1 | M2 )

SHE KDF(K, C):   OUT_1 = ENC_ECB(OUT_0, K) ⊕ K ⊕ OUT_0        (OUT_0 = 0¹²⁸)
                 out   = ENC_ECB(OUT_1, C) ⊕ C ⊕ OUT_1

KEY_UPDATE_ENC_C = 01015348 45008000 00000000 000000B0h
KEY_UPDATE_MAC_C = 01025348 45008000 00000000 000000B0h

Implemented in key_manager.c:329 (SecLib_CalculateKdfSHE — runs on ICUSE by bouncing derived keys through the RAM_KEY slot), :182 (SecLib_GenerateM2), :273 (SecLib_GenerateM3). Matches HIS SHE spec / manual §4.4.

6 · Security ledger

PropertyStatusNote
Integrity✅bit flips anywhere ⇒ verify fails ⇒ zeroize / INTEGRITY_FAILED
Authenticity✅forgery needs the slot key; it can't leave ICUSE, is CMAC-only (KU), frozen (WP)
Confidentiality❌payload plaintext by design; pair with an encryption key if needed
Freshness❌whole-block replay of older valid copies is undetected; odometer blocks address rollback at the application layer

7 · Variant & debugging notes

  • KEYRAM_AS_KEY: DATASTORE_KEY ≡ RAM_KEY (volatile). data_protection.c:7 hard-codes a dev-only key (pKeyRam[]) reloaded on every read/write — never for production; the default build's TRNG + WP flow is the secure one.
  • Slot empty at verify time ⇒ ICUS ERC_KEY_EMPTY (0x008) → E_VC_SECBOOT_ICUS_KEY_EMPTY.
  • Re-provision attempt after WP ⇒ ERC_KEY_WRITE_PROTECTED (ERR5) — enable path treats this as "already enabled" (secure_boot.c:142).
  • M1M2M3 rejected (CMAC/counter/UID) ⇒ ERC_KEY_UPDATE_ERROR (ERR6).

3 · Mandatory integration checklist

  1. Extend the SecLib slot whitelist: add case KEY_5: to SecLib_MACGenerate (crypto_library.c:238–246) and SecLib_MACVerify (crypto_library.c:319–327) — otherwise every CMAC on KEY_5 fails with "keyId not supported".
  2. Bridge CryWrapper → security lib: read the 16 derived bytes from the group-key element (or pass them directly) and fill SecLib_KeyDataType; wipe the software copy once CMD_LOAD_KEY succeeds.
  3. Respect the RAM_KEY ownership policy while K1/K2 derivation bounces through the RAM slot (key_manager.c:235, 287) — no concurrent RAM_KEY user during the load.
  4. Decide WP before first provisioning — one-way latch; rotating ECDH keys cannot live in a WP slot.
  5. Update the assurance workproduct: notes §6 boundary ("persistent slots never written by the ECC path") is deliberately broken by this requirement — record the change and the justification.
  6. Verify: CMAC generate + verify round-trip with the new slot (adapt secure_boot.c:463–480); then confirm SecOC frames authenticate.

4 · Assurance boundaries (from notes §7 — unchanged by KEY_5)

  • ECC is software (mbedtls ECP 2.27.0 port + fork bignum); ICUSE has no ECC engine. "HPSE protection" claims must not be made for the negotiation path.
  • Entropy source: ICUS PRNG via SecLib_RandomGenerate; CS.00098 compliance to be confirmed by the security team.
  • Hardening present: on-curve peer point validation (invalid-curve rejection), unbiased scalars, coordinate blinding, zeroization on every exit path.
  • Ephemeral d lives in CPU RAM only, never in NVM or a persistent slot.

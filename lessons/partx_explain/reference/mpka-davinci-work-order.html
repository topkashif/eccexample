DaVinci configuration work order: Csm, CryIf and Crypto containers for MPKA key references

Container-by-container entry guide for DaVinci Configurator, grounded in the checked-in BSWMD files, the MPKA implementation, the Crypto_30_CryWrapper provider and the security-folder replacement layer. Illustrative names and numeric IDs are marked as examples.

Scope and evidence boundary This PC has no DaVinci Configurator and cannot compile the target. Every container and parameter below is taken from the local BSWMD definitions (.scratch/bswmd_*.txt extracts), the component sources and the project headers. Nothing here claims a generated, validated or executed configuration. Steps 8-10 run on the IPC build PC and target.

0 · Fix four decisions before opening DaVinci

#DecisionGuidance
D1Which generated artifacts are consumed by the custom runtimeConfigure Csm, CryIf and Crypto containers fully in DaVinci even though Vector Csm.c/CryIf.c are not linked. The containers make MPKA's CDD references resolvable, let DaVinci validate the reference graph, and generate the Cfg headers (Csm_Cfg.h/Csm_Types.h element IDs, key IDs) that the security-folder implementation must agree with. Ownership rule: exactly one implementation per Csm_*/CryIf_* symbol at link time — the security folder's, with the generated headers as the shared ID contract. If the project's generator setup cannot emit Csm/CryIf at all, fall back to a hand-maintained ID header in the security folder that replicates the tables below verbatim.
D2Shared-value encoding: VKEYM_MPKA_SHARED_VALUE_LENGTH_X (28 B) vs ..._X_AND_Y (56 B)Must match EVCU and the approved spec revision. It also has a direct configuration consequence: the wrapper selects the ECDH output encoding from the configured size of the SHAREDVALUE element (28 → x-only, 56 → x||y), see Crypto_30_CryWrapper_Hw.c:1033-1046 region (CalcSecret length check). Every dependent size in §2 follows this choice.
D3How SecOC gets the committed final keyOption A: SecOC MAC job references MAC_Final_2 directly (final key stays non-readable). Option B: the security-folder adapter reads the 16-byte key via Csm_KeyElementGet into ICUS KEY_RAM (final key element must be RA_ALLOWED). This single bit decides the read-access column in §2.
D4Is the ICUS crypto driver (Cry_30_Rh850Icus) retained as a second provider?The MPKA key path needs only the CryWrapper software provider (ECDH/KDF via SecLib_Ecc/mbedtls). If SecOC CMAC/RNG run through a retained ICUS module, it becomes a second Crypto driver object with its own CryIf channel and the SecOC jobs route via that channel. If the adapter owns CMAC, no ICUS driver object is configured.

1 · Import BSWMDs and add the modules

  1. In the DaVinci project, import the BSWMD files shipped with the exact SIP delivery the sources came from: vKeyM_MPKA_bswmd.arxml (module name Cdd), Csm_bswmd.arxml, CryIf_bswmd.arxml, Crypto_30_CryWrapper_bswmd.arxml (module name Crypto), and Cry_30_Rh850Icus_bswmd.arxml only if D4 = retained.
  2. Check file versions in each BSWMD's ADMIN-DATA against the delivery release note. A BSWMD from a different release can silently change parameter multiplicity (this workspace's MPKA BSWMD is revision 4.02.00 lineage).
  3. Add BSW modules: Csm, CryIf, Crypto (CryWrapper), plus MPKA's Cdd module. Even with the custom runtime linked later, the modules must exist for references to resolve and for the generator to emit the Cfg headers (decision D1).

2 · Crypto module (Crypto_30_CryWrapper) — bottom-up: elements, key types, keys, driver object

2.2 CryptoKeyTypes

Create three CryptoKeyType containers (KEX_Group_2_KeyType, KDF_Input_2_KeyType, MsgKey16_KeyType); each references its CryptoKeyElement set via CryptoKeyElementRef. A key type is a layout, not a value.

2.4 CryptoPrimitives and CryptoDriverObject

  • No primitive is configured for the MPKA key path. MPKA calls direct key-ID APIs; the wrapper's ECDH/KDF is reached through the key-management API (Crypto_30_CryWrapper_Hw_KeyExchangeCalcPubVal → SecLib_EccGenerateEphemeralKey :909; ...CalcSecret → SecLib_EccComputeSharedSecret :991; ...KdfX963Sha256 :1086; Crypto_30_CryWrapper_KeyDerive KeyManagement.c:1270-1302). This wrapper BSWMD's CryptoPrimitiveService enum has no key-exchange/KDF literals at all — do not block on "missing ECDH primitive"; if your delivery's enum offers one, follow the delivery.
  • If the wrapper also serves job-based services (it does not in the current integration), each would need a CryptoPrimitive with service/family/mode/secondary-family matching the Csm primitive, referenced by the driver object.
  • CryptoDriverObject (one): CryptoDriverObjectId = 0; CryptoDriverObjectQueueSize is fixed at 1 in this BSWMD (min=max=1); CryptoPrimitiveRef only for primitives that actually exist per above.
  • CryptoGeneral: CryptoDevErrorDetect per project, CryptoMainFunctionPeriod 0.01 (only relevant if the wrapper module itself is generated/linked), CryptoNvMEnableSetRamBlockStatus per persistence design.

4.2 CsmGeneral

  • CsmDevErrorDetect, CsmVersionInfoApi, CsmSafeBswChecks per project.
  • CsmSwcMainInterfaceVersion default R21_11 — keep unless the project pins another AUTOSAR version.
  • CsmMainFunctionPeriod 0.01 (scheduling of the Csm main function; with the custom runtime, the security folder owns the actual scheduler hookup).
  • CsmSymKeyMaxLength = 16 (default) covers the AES-128 keys; CsmAsymPublicKeyMaxLength only matters for signature services.

4.3 Jobs, primitives, queues — SecOC MAC only

It never calls Csm_JobKeyExchangeCalcPubVal/Csm_JobKeyDerive. So the CsmJobKeyExchangeCalcPubVal/CalcSecret/KeyDerive primitive containers in this BSWMD are not configured for MPKA. 6 · Reference-resolution audit before generating

  1. Every Cdd key ref resolves to exactly one CsmKey; every CsmKeyRef to exactly one CryIfKey; every CryIfKeyRef to exactly one CryptoKey; every CryptoKeyTypeRef to a key type whose elements all exist.
  2. ID uniqueness per namespace: CsmKeyIds unique among Csm keys; CryIfKeyIds unique; CryptoKeyIds unique; CryptoKeyElementId unique within one key type (element 1 legitimately repeats across key types — PASSWORD, CIPHER_KEY and SHAREDVALUE are all 1 in the checked-in header but live in different keys).
  3. Element numeric IDs equal the CRYPTO_KE_* values in the headers MPKA compiles against (§2.1 table). This is the single most error-prone mapping — check it name by name.
  4. Sizes: every element MPKA writes or copies has capacity ≥ the written length; SHAREDVALUE size equals the D2 encoding exactly (28 or 56 — not "56 with partial access").
  5. Access: MPKA-written elements are WA_ALLOWED; derive/copy targets are WA_INTERNAL_COPY; private/shared/password material is RA_DENIED unless D3 = Option B (then final-key element 1 = RA_ALLOWED).
  6. CryIfMaxSizeOfKeyElement ≥ 64, CryIfMaxNumberOfKeyElements ≥ 9.
  7. Jobs exist only for SecOC MAC (and optional RNG); no key-exchange/KDF jobs or primitives were created "for MPKA".

7 · Generate and hand over to the security folder

  1. Run the generator; export the ECUC/ARXML and the generated Cdd_Cfg.c/h, Csm_Cfg.h, CryIf_Cfg.h, wrapper Cfg headers.
  2. Diff the generated key-ID macros against §4.1's illustrative table and record the real numbers in the integration note.
  3. The security-folder implementation must, per symbol ownership (D1):
    • implement the direct key APIs MPKA calls: Csm_KeyElementSet, Csm_KeyElementCopy, (Csm_KeyElementGet only if D3 = Option B), Csm_KeySetValid, Csm_KeyCopy, Csm_KeyExchangeCalcPubVal, Csm_KeyExchangeCalcSecret, Csm_KeyDerive;
    • resolve the four CsmKeyIds and forward element IDs to the wrapper's key storage/provider functions (Crypto_30_CryWrapper_KeyManagement.c, Crypto_30_CryWrapper_Hw.c → SecLib_Ecc*/mbedtls ECP);
    • enforce the access/valid semantics of §2.1 (validity is separate from written bytes: MPKA pairs writes with Csm_KeySetValid);
    • implement the SecOC MAC job dispatch (existing adapter secoc_securitylib_csm_wrapper.c) against CSM_MAC_FINAL_2 with the 7-byte input / 3-byte MAC contract.
  4. Keep one owner per global symbol in the link map — no duplicate Csm_* definitions and no accidental Vector Csm.c/CryIf.c object files.
